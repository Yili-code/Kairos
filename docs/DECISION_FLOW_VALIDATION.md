## 真實外部執行與隔離範圍

前三個案例修正前後各進行一輪實際外部抓取與既有 Gemini 評估，保留原始來源文字、模型輸出、來源引文、判斷、抓取紀錄與卡片。每輪三案，未改服務的每輪三場模型上限；未量測或宣稱實際 API 費用。

輸入取自既有線索／種子，透過隔離的候選 repository 跑 ingest、解析、模型、確定性判斷、排序與卡片產生。來源不是新的全網發現測試；Telegram 以捕捉 client 驗證，未因此傳送訊息，也未寫正式候選或寄信。受控測試則使用合成規則確認完整正例與反例，不能當成真實合格競賽。

另以修正前保存的同一份來源與模型輸出重播，排除模型波動與網站更新：

額外四個受控錯誤模型斷言，原先均可通過評估：外校封閉資格、僅有排除清單、擅自假設國籍，以及引文沒有支持的未來日期。修正後分別 rejected／pending；這是錯誤注入驗證，不表示真實模型四次都犯過這些錯，也不是整體準確率。

第二次真實模型抽取又漏掉書藝智生簡章中的使用權條款。新程式只從教育／政府來源找唯一、明確的參賽者或得獎者條文，補回原文與來源；不同條文不任選，網站著作權頁尾不當成參賽授權。這是文字擷取，不是法律解釋，也不表示授權條款適合使用者接受。

## 推薦呈現與重複

- 卡片現在明說值得開始製作、僅適合查證，或存在明確衝突；獎金、期限、資格各有直接證據連結。資格規則原文、已標示的日期／費用預設、未實測的工時與工具費仍分開呈現。
- 使用正規化網址與同一截止資訊防止同網址不同參數順序重複推薦；考量已送出與送達未確認紀錄。受控流程兩個變體只產生一張卡，後續掃描不再產生第二張。
- 這不等於解決所有跨校轉載；不同網址、不同主辦平台或沒有共同識別資訊的同活動仍需比對。沒有單憑相似名稱自動合併或刪除正式紀錄。

## 是否足以支持申請決策

目前可幫助排除明確不符、核對資格與期限，並指出下一個要查的條件；本輪真實樣本仍不足以支持直接報名、花錢或開始完整製作。主要缺口在主辦條款與製作可行性，不需要為此向使用者索取一整份新背景。

若後續競賽明確要求國籍／護照、居留期間、其他學籍、團隊或既有參賽紀錄，才需要逐項確認。模型引文語義檢查仍是保守、有限規則，並非涵蓋全世界資格與法規的判定器；其他欄位仍需核對原文。小樣本結果不能推估整體推薦準確率或得獎率。
